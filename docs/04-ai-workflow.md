# AI Workflow

Цель этого документа - экономить контекст и лимиты при разработке с Codex/ChatGPT Plus.

## Как ставить задачи

Лучший формат:

```text
Сделай следующий шаг из roadmap: <название>.
Сначала проверь docs/, потом реализуй, запусти тесты и обнови документацию.
```

Для багов:

```text
Ошибка: <что происходит>.
Ожидаю: <что должно быть>.
Проверь причину, исправь, добавь тест или проверку.
```

## Как экономить лимиты

- Не пересказывать весь проект в каждом сообщении.
- Ссылаться на конкретный документ: `docs/02-roadmap.md`, `docs/03-architecture.md`.
- Просить один законченный шаг за раз.
- Большие решения фиксировать в markdown-файлах.
- Не держать огромные обсуждения в одном чате, если можно сохранить результат в repo.
- После каждого этапа просить короткий статус: что изменено, что проверить, что дальше.

## Правило спринта

Каждый спринт должен давать проверяемый результат:

- код;
- тест;
- локальный запуск;
- обновленная документация;
- понятный следующий шаг.

## Приоритет использования моделей

- Для проектирования архитектуры и сложных ошибок использовать более сильную модель.
- Для механических правок, CRUD, документации и повторяющихся задач использовать более легкий режим/модель, если доступно.
- Если лимит близко, прекращать генерацию новых фич и фиксировать текущий статус в документах.
