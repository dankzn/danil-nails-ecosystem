## Публичный сайт (apps/site)

Отдельный от CRM deployment: премиальный маркетинговый сайт, деплоится на Vercel.
Развивается параллельно фазам CRM, не блокирует soft launch.

CRM (`apps/web`) и API (`apps/api`) переезжают с Render на Vercel (два отдельных
проекта, БД остаётся на Supabase — переносить данные не нужно). Код готов
(serverless-обёртка для Fastify, `vercel.json`, CORS под новый домен CRM) —
см. `docs/10-vercel-api-crm-deployment.md`. Сам деплой (создание Vercel-проектов,
переменные окружения) делается вручную в дашборде Vercel — остановка Render
после проверки. ⏳

- Премиальный дизайн "Obsidian & Garnet" (тёмная тема, гранат/шампань, Playfair Display + Manrope). ✅
- Скролл-анимации, magnetic-кнопки, курсор-glow — с отключением через `prefers-reduced-motion`/`pointer: coarse`. ✅
- Многостраничная структура: главная, услуги, работы, мастер, контакты. ✅
- Мультиязычность: ru/en/es/fr через `app/[lang]` статический роутинг (без middleware, совместимо с `output: "export"`). ✅
- Hero-раздел без шаблонного "текст слева / фигура справа": центрированный заголовок с параллакс-blob позади текста. ✅
- Реальная регистрация, вход и личный кабинет (профиль клиента) через API. ✅
- Реальная форма онлайн-записи на странице контактов: услуга, мастер, дата, свободное время из CRM, гостевая или клиентская запись — подтверждается вручную. ✅
- Реальные контакты, Telegram-бот для записи — после того как появится реальный канал (зависит от Telegram bot).
- Реальные фото работ и брендинг — заменят цветовые заглушки, когда будут готовы материалы.
- Список записей клиента в личном кабинете — следующий шаг поверх онлайн-записи.

- Улучшение CRM UX.
- Права доступа и аудит действий.
- Раздел `Персонал`: сотрудники, оргструктура и назначения руководителей. ✅
- Системные справочники должностей, организаций, географии и типов оргобъектов/руководителей. ✅ (кадровые статусы/виды занятости, кассы и виды начислений остаются enum'ами — справочниками станут вместе с соответствующими фичами)
- Должности: пометка «внутренняя» (не видна клиентам и на сайте, только в CRM), и несколько должностей у одного сотрудника (например, «Основатель» + «Мастер маникюра») — на сайте показываются ВСЕ публичные должности сотрудника (через " · "), внутренние туда никогда не попадают. ✅
- На странице мастеров и в карточках команды — кнопка «Записаться» у каждого сотрудника, которая ведёт в форму записи с предвыбранным этим мастером. ✅
- Переводы должностей (ru/en/es/fr) в справочнике и карточке сотрудника. ✅
- Публичная страница мастеров на сайте (`apps/site`), подтягивающая имя, переведённую должность и фото бронируемых сотрудников из CRM в реальном времени (без пересборки сайта). Все мастера показаны РАВНОЗНАЧНО, без выделения кого-то отдельной большой карточкой. У должности есть отдельный флаг «Мастер» (по умолчанию включён — если снял пользователь явно, значит должность административная): сотрудники без хотя бы одной такой должности (например, чисто административный персонал — Основатель, Сооснователь, SMM-менеджер) на этой странице не показываются (для них в будущем будет отдельная страница «Административный персонал»). Флаг «по умолчанию включён», а не наоборот, специально — чтобы новая или уже существующая публичная должность не роняла её обладателя со страницы мастеров молча. ✅
- Загрузка фото сотрудника в CRM (карточка сотрудника → фото профиля) с хранением прямо в основной базе Postgres (таблица `StaffPhoto`, отдельно от остальных полей сотрудника, чтобы не раздувать обычные запросы) и показом и в CRM, и на сайте. Внешний сторадж не используется — не нужно ни отдельного проекта, ни его настройки. ✅
- Полная публичная карточка мастера (клик по карточке в команде мастеров → отдельная страница `/master/profile/?id=...`): имя, стаж работы (считается на сервере из даты приёма, сама дата приёма наружу не отдаётся), фото, «Моя философия» и видео работ (YouTube/Vimeo, встраивается плеером). Кнопка «Записаться» у каждой карточки ведёт в форму записи с этим мастером и больше не конфликтует с кликом по самой карточке. Заодно исправлена утечка: поле `StaffProfile.bio` («Служебная информация» в CRM) раньше ошибочно уходило в публичный `/v1/staff` — теперь для публичной карточки используются только специально предназначенные для этого поля (`philosophy`, `worksVideoUrl`), а `bio` остаётся строго внутренним. ✅
- Заготовка фильтра по стране/городу на странице мастеров: `/v1/staff` уже отдаёт город и страну сотрудника (используются уже существующие поля `StaffProfile.cityId/countryId`, новых полей не потребовалось), UI фильтра полностью рабочий (страна → город каскадно), но остаётся скрытым, пока у всех мастеров одна и та же локация — появится сам собой, без доработок кода, как только в базе будет вторая страна или город. ✅
- Финансовые отчеты.
- Таблица зарплаты, настройки процентов по должностям и детализация начислений.
- Формирование расчётных листов PDF по согласованному шаблону.
