# ERP/HCM: что стоит перенять и что уже сознательно не берём

Разбор практик из ERP (управление ресурсами) и HCM (управление персоналом) систем применительно к Danil Nails — с чем уже совпадаем, что стоит добавить и что уже осознанно отклонено раньше (чтобы не предлагать по кругу).

## Уже фактически реализовано в духе ERP/HCM

- **Ролевой доступ (RBAC)**: owner/admin/master/client с разными правами — стандартная ERP-практика.
- **Модерация и история изменений**: подтверждение записи вручную, `AppointmentEvent` как журнал статусов, история назначения внутренних тегов (автор, дата) — это и есть ERP-style audit trail.
- **Оргструктура**: подразделения, города, страны, назначение руководителей — заложена основа под мультилокацию (Испания), это ровно то, что ERP называют multi-entity/multi-location.
- **HR-блок**: приём/увольнение, документы сотрудника, обучение (trainings), зарплата с настраиваемыми процентами — это уже мини-HCM, не просто CRM.
- **Точка дозаказа на складе** (`reorderThreshold`) — базовый ERP min-stock паттерн.

## Уже сознательно отклонено (не предлагать снова)

- **Точный учёт расхода материалов по граммам с себестоимостью услуги** — прямо описано в `01-mvp-scope.md` и `05-requirements.md` как избыточное для ногтевого сервиса (актуально для окрашивания волос, не для нас).

## Стоит добавить — по приоритету

### 1. Партии материалов со сроком годности (прямое продолжение задачи со списаниями)

Только что добавили причину списания (брак/срок годности/повреждение/утеря), но сам факт истечения срока сейчас никто не увидит заранее — админ узнаёт постфактум, когда уже приходится списывать. Классический ERP-паттерн — партии (lots/batches):

- у материала может быть несколько партий с датой прихода и сроком годности;
- расход/списание идёт по FEFO (first-expired-first-out) — сначала используется то, что портится раньше;
- дашборд показывает предупреждение за N дней до истечения срока — тот же принцип, что и в трекере прихода клиентов, только для склада.

Это средняя по размеру задача (новая модель `MaterialBatch`, привязка движений к партии, виджет предупреждений). Отдельно от причин списания, которые уже сделаны.

### 2. Отслеживание сертификатов и лицензий мастеров (HCM-паттерн, тот же принцип "истекает — предупреди заранее")

В ногтевой индустрии актуальны: санитарная книжка, сертификаты о повышении квалификации. Сейчас в карточке сотрудника есть "обучение" (trainings), но нет структурированного срока действия и предупреждения об истечении. HCM-системы всегда держят список требований к должности со сроками и напоминают заранее — то же самое, что нужно для партий материалов (см. п.1), только для людей.

### 3. Учёт отпусков и больничных как отдельная сущность

Сейчас отпуск — это просто исключение в графике мастера (day-level блокировка). HCM обычно ведёт это отдельно от графика: баланс дней отпуска, история использования, тип отсутствия (отпуск/больничный/без содержания). Пока при одном мастере не критично, но при росте команды понадобится — стоит держать в уме при проектировании, не обязательно делать сейчас.

### 4. Отчёт по низким остаткам склада как отдельный виджет

`reorderThreshold` уже есть в данных, но администратор видит "мало осталось" только зайдя в карточку конкретного материала. ERP обычно выносит это на дашборд отдельным блоком (как список "Скоро придут" для записей) — все материалы ниже точки дозаказа, сразу с рекомендацией закупить. Небольшая задача, использует уже существующие данные.
